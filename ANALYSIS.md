# StealthyIMU Repository Analysis

## Phase 0: Repository Analysis

### 1. Existing Files Review

#### `train.py`
- **Training Loop:** Uses SpeechBrain's `Brain` class (`sb.Brain`). The training loop calls `fit_batch()` which runs `compute_forward()` and `compute_objectives()`. It uses teacher forcing during training and beam search during evaluation. 
- **Optimizer:** The optimizer is defined in the hparams file as `torch.optim.Adam`.
- **Loss Function:** Negative Log-Likelihood (NLL) loss (`speechbrain.nnet.losses.nll_loss`) applied to the seq2seq decoder output.
- **Data Loading Pattern:** Uses `sb.dataio.dataset.DynamicItemDataset`. The dataset is loaded from generated CSV files. The audio pipeline takes a filename (variable name `wav`), replaces the extension with `.accnpy`, and loads a NumPy array, specifically extracting the 4th row (`signal[3,:]`). The text pipeline uses a SentencePiece tokenizer to encode target semantic strings.

#### `hparams/baseline.yaml`
*(Note: The repository contains `hparams/open_source.yaml`, not `baseline.yaml`. We have reviewed `open_source.yaml`.)*
- **Model Dimensions:** 
  - CNN: 2 blocks, channels (64, 128), kernels (3, 3)
  - RNN: 4 layers, 256 bidirectional neurons
  - DNN: 2 blocks, 256 neurons
  - Decoder: GRU with 256 hidden size, key-value attention with dim 256
  - Output Neurons (Vocab Size): 51
  - Embedding Size: 64
- **Learning Rate:** 0.0003 with `NewBobScheduler` (annealing factor 0.8)
- **Batch Size:** 8
- **Number of Epochs:** 20
- **Tokenizer Config:** Unigram SentencePiece model located at `pretrain/51_unigram.model`.
- **Data Paths:** `data_folder: /data/SoK/StealthyIMU_organize/`, `file_name: metadata/stealthyIMU_all_relative.csv`.
- **Checkpoint Paths:** Saves to `results/BPE51_all_opensource_test/<seed>/save`.

#### `eval/eval.py`
- **Metrics Computed:**
  - **TER (Type Error Rate):** Measures whether the `action` type (command type) is correctly identified.
  - **SER (Sentence Error Rate):** Considers a prediction correct only if both the `action` and all `entities` perfectly match the ground truth.
  - **SEER (Single Entity Error Rate):** Computes the error rate by treating the action and each individual entity as independent units to be matched.
- **Reading Format:** It parses strings formatted like Python dictionaries (e.g. `{"action": "...", "entities": [...]}`) from log text files, replacing single quotes with double quotes to load them as JSON objects.

#### `pretrain/tokenizer.ckpt`
*(Note: The file present is `pretrain/51_unigram.model`.)*
- **Vocabulary Size:** 51 tokens (based on `output_neurons: 51` in the YAML).
- **Tokenization Scheme:** Unigram (SentencePiece).

## Discrepancy Resolutions
- **Discrepancy 1 (File Naming):** No files were renamed. `hparams/open_source.yaml` is used as the base config and `pretrain/51_unigram.model` is used directly as the tokenizer.
- **Discrepancy 2 (CNN Blocks):** Created `hparams/paper_exact.yaml` which sets `cnn_blocks: 1`. Phase 1 will be run twice (using `open_source.yaml` for baseline repo numbers, and `paper_exact.yaml` for exact paper match).
- **Discrepancy 3 (Epochs):** Both `open_source.yaml` and `paper_exact.yaml` were updated to use 30 epochs instead of 20.

## Task 4: Dataset Inspection Findings
- **Command Types & Samples:** We found 8 command types (cleanair, cleanstock, cleansun, cleantime, Navigation, newmock, ny_navi, Reminder) with a total of 16,128 samples. The paper listed 23 command types and 44,691 samples, indicating this dataset is a subset.
- **.accnpy Inspection:** `0051f94a-fb04-3059-8352-cfa95a79e151.accnpy` has shape `(4, 3471)`, dtype `float64`. Row index 3 has non-trivial signal.
- **.wav Inspection:** The corresponding `.wav` is 16kHz, mono, 6.945s long. There are two WAVs per folder (`{uuid}.wav` and a timestamped one); the CSV points directly to `{uuid}.wav`.
- **Semantics Label:** Uses `|` instead of `,` inside the dict string representation, matching the regex/replace parsing logic found in `eval.py`.
- **Split Column:** No existing column defines the train/val/test splits. The 8:1:1 split must be generated manually.
